HamsTTS test client

Swagger's /docs page can open a WebSocket connection but can't send frames through it (so it just sits there — that's not a server bug), and its binary-response viewer for POST /tts doesn't give you a clickable player. Both are real client-side limitations of Swagger UI, not this server — this page is a real client for both.

1. Non-streaming (POST /tts) — simplest, returns a full WAV


2. Streaming (WebSocket /tts/stream) — plays audio as each chunk arrives
